# HOI4 輸送船・輸送航路・通商破壊後の効率処理

> 対象: HOI4 1.17系の提供Ghidraプロジェクトと、Workshop `820039020`（innovative balance v13.00）  
> 中心テーマ: 輸送船を撃沈されたとき、資源輸入・海上補給などがどの条件で減少または完全停止するか

## 1. 結論

輸送船が1隻撃沈されたとき、ゲームが無条件に航路を切断するわけではない。撃沈は次の二つの経路で輸送量へ影響する。

```text
輸送船を撃沈
  ├─ A. 撃沈海域の「船団輸送効率」を低下させる
  │      同じ国の、その海域を通る各輸送経路へ波及
  │
  └─ B. 国が保有する輸送船を1隻失わせる
         予備が足りなければ、経路への配属船団数が不足
```

MOD `820039020` ではAの損失倍率が非常に大きく、最低保証も0%である。そのため、**撃沈海域を通る必要船団総数が3隻以下なら、初期効率100%から1隻撃沈しただけで海域効率が0%になる。**

```text
CONVOY_EFFICIENCY_LOSS_MODIFIER = 3.75
CONVOY_EFFICIENCY_MIN_VALUE     = 0.00
```

必要船団総数が4隻なら1隻撃沈後は6.25%、5隻なら25%、10隻なら62.5%となる。「1隻で常に切れる」のではないが、小規模な島嶼補給や小さな資源輸送では実際に1隻で完全停止しうる。

また、効率は攻撃された個別航路だけでなく、**被害国ごと・海域ごと**に保持される。同じ海域を同じ国の資源輸入、海上補給などが共有していれば、1回の撃沈が複数用途へ同時に波及する。

## 3. 輸送船1隻が沈んだときの呼び出し

海戦処理 `FUN_1418d47e0` は、破壊対象が通常艦ではなく `CConvoyShip` だった場合に輸送船の破壊処理を行う。その後、輸送船の所有国と撃沈海域を求めて次を呼ぶ。

```text
FUN_140e75a90(被害国の輸送管理, 撃沈海域ID, 1)
```

第3引数は撃沈数で、この呼び出しでは常に `1`。したがって、海戦結果をまとめて一度だけ処理するのではなく、**破壊された輸送船1隻ごとに損失が加算される。**

この経路が呼ばれる条件は輸送船の破壊確定である。

- 発見しただけでは効率損失は発生しない。
- 海戦を開始しただけでも、この撃沈由来の効率損失は発生しない。
- 損傷させたが生存した輸送船については、この関数は呼ばれない。
- 実際に沈没した輸送船1隻につき1回呼ばれる。

船団襲撃任務効率や護衛効率は、海戦を発生させられるか、どれだけの艦が初期参加するか、輸送船を実際に撃沈できるかには影響する。しかし、**1隻を沈めた後の効率低下量そのものには襲撃側の攻撃力、任務効率、提督能力、護衛効率は入っていない。**

## 4. 撃沈による海域効率低下式

### 4.1 正規化した式

次を置く。

```text
E = 撃沈直前の対象海域効率（0～1）
K = 今回撃沈された輸送船数
N = その海域を通る必要船団総数
L = CONVOY_EFFICIENCY_LOSS_MODIFIER
```

`N > 0` の場合、`FUN_140e75a90` の式は次になる。

```text
LossRatio = K / N
Loss      = LossRatio × L

Enew = max(0, E - Loss)
```

輸送船1隻ごとの呼び出しでは `K = 1` なので、通常は次である。

```text
Enew = max(0, E - L / N)
```

MOD値 `L = 3.75` を入れると、

```text
Enew = max(0, E - 3.75 / N)
```

となる。

### 4.2 機械語に近い固定小数点式

exeは概ね次の順序で計算している。

```text
loss_ratio_fixed
  = (撃沈数 × 10000000000)
    / (必要船団総数 × 100000)

loss_fixed
  = loss_ratio_fixed × LOSS_MODIFIER_fixed / 100000

regional_efficiency_fixed
  = max(0, regional_efficiency_fixed - loss_fixed)
```

これは正規化すれば前節の `K / N × L` と同じである。

### 4.3 「100%の船団を失う」の意味

defineコメントには、損失倍率が0.5なら短期間に船団の100%を失ったとき効率が50%落ちる、と書かれている。exeもこの説明どおり、撃沈数を海域の必要船団総数で割っている。

このMODは `L = 3.75` なので、理論上は必要船団総数の、

```text
1 / 3.75 = 約26.67%
```

を回復前に失えば、初期100%から0%へ到達する。

## 5. 分母Nは何を数えているか

### 5.1 個別海戦の参加輸送船数ではない

`FUN_140e78480` は日次更新時に、国が持つ海域別レコードの必要船団数を一度0へ戻す。その後、複数の輸送経路コレクションを走査し、それぞれについて次を行う。

```text
その輸送経路の必要船団数 = CConvoyClient + 0x2c

for 経路が通る各海域:
    海域の必要船団総数 += その輸送経路の必要船団数
```

したがって分母 `N` は、

- 今回の海戦へ出現した輸送船数
- 今回撃沈された個別航路だけの必要数
- 国が保有する輸送船在庫の総数

のどれでもない。

正確には、**被害国がその海域を通している対象輸送経路について、各経路の必要船団数を合計した海域別の値**である。

### 5.2 同じ航路は通過する各海域で数えられる

必要船団10隻の航路が海域A、B、Cを通るなら、各海域の分母へ10隻ずつ加算される。ただし撃沈損失が記録されるのは、実際に輸送船が沈んだ海域である。

```text
必要船団10隻の航路: A → B → C

Bで1隻撃沈
  Aの効率: 変化なし
  Bの効率: 3.75 / N_B だけ低下
  Cの効率: 変化なし
```

別の航路もBを通っていれば、その航路の必要船団数も `N_B` へ加算される。交通量の多い海域ほど1隻当たりの効率損失が小さく、小規模航路しかない海域ほど大きくなる。

### 5.3 同じ国の別航路にも波及する

効率は個別 `CConvoyClient` ではなく、被害国の海域別レコードへ保存される。航路効率を計算するときは、その航路が通る各海域の効率を被害国のレコードから取得する。

したがって、同じ国の複数航路が同じ海域を共有していれば、攻撃された航路以外にも同じ海域損失が使われる。資源輸入と海上補給が同時に悪化するのは、この構造で説明できる。

別の国は別の海域効率レコードを持つため、同じ海域を通っているだけで他国の輸送効率まで下がるわけではない。

## 6. MODで1隻撃沈した場合

初期海域効率を100%、回復や別の既存損失がないものとする。

| 海域の必要船団総数N | 1隻の低下量 | 撃沈後の海域効率 |
|---:|---:|---:|
| 1 | 375% | 0% |
| 2 | 187.5% | 0% |
| 3 | 125% | 0% |
| 4 | 93.75% | 6.25% |
| 5 | 75% | 25% |
| 8 | 46.875% | 53.125% |
| 10 | 37.5% | 62.5% |
| 20 | 18.75% | 81.25% |
| 50 | 7.5% | 92.5% |
| 100 | 3.75% | 96.25% |

### 6.1 完全遮断に必要な累積撃沈数

分母が一定で、回復が始まる前に連続して撃沈したと仮定すると、初期100%から0%にする必要数は次になる。

```text
Kcut = ceil(N / 3.75)
```

| 必要船団総数N | 0%に必要な撃沈数 |
|---:|---:|
| 1～3 | 1 |
| 4～7 | 2 |
| 8～11 | 3 |
| 20 | 6 |
| 50 | 14 |
| 100 | 27 |

一般形では、撃沈前の効率が `E` の場合、

```text
Kcut = ceil(E × N / L)
```

となる。

### 6.2 なぜ必要船団4隻でも「消えた」ように見えるか

必要船団4隻なら、理論上の海域効率は0%ではなく6.25%残る。しかし、最終輸送量にはさらに船団充足率が掛かる。輸送対象が少量の場合は、UI上の整数化によって供給・資源が0に見える可能性もある。

そのため、画面で0になったことだけから、内部海域効率が厳密に0%だったとは限らない。経路ツールチップの「航路効率」「必要船団」「配属船団」を同時に確認する必要がある。

## 7. 航路全体への合成

撃沈関数が更新するのは個々の海域効率である。実際の輸送経路へ適用するときは `FUN_140c59c50` が、

1. 経路に必要な船団のうち何隻を配属できたか
2. 経路上の各海域がどれだけ通商破壊で妨害されているか

を合成する。

### 7.1 船団充足率

輸送経路オブジェクトでは次の二つが分離されている。

```text
必要船団数 = CConvoyClient + 0x2c
配属船団数 = CConvoyClient + 0x28
```

配属数は0～必要数へ丸められ、充足率は次になる。

```text
A = 配属船団数 / 必要船団数
```

必要10隻に対して7隻しか配属できなければ `A = 70%`。国に予備輸送船があれば撃沈分を補充できるため、1隻沈んでも直ちにAが下がるとは限らない。予備がなければ、物理的な船団不足としてAも低下する。

### 7.2 経路上の海域損失

経路が通る各海域の効率を `Ei` とする。exeは各海域の損失 `1 - Ei` を加算している。

```text
R = clamp(1 - Σ(1 - Ei), 0, 1)
```

平均ではなく、損失の加算である。

例として、三つの海域を通る経路を考える。

```text
海域A = 90%  → 損失10%
海域B = 80%  → 損失20%
海域C = 100% → 損失 0%

R = 1 - (0.10 + 0.20 + 0.00)
  = 70%
```

海域AとBがそれぞれ40%まで落ちていれば、損失合計が120%なので経路側は0%へ丸められる。

### 7.3 MODでの最終形

MODは最低値が0なので、実用上は次で読める。

```text
最終輸送効率 ≒ A × R

A = 配属船団数 / 必要船団数
R = clamp(1 - Σ(1 - 海域効率), 0, 1)
```

例:

```text
必要船団10隻
配属船団8隻 → A = 80%

経路上の海域損失合計37.5%
→ R = 62.5%

最終輸送効率 ≒ 0.80 × 0.625 = 50%
```

輸送船撃沈は、海域効率Rと、輸送船在庫不足によるAの両方を同時に悪化させうる。

## 8. 完全停止する条件

### 8.1 撃沈による海域効率0%

MODでは `CONVOY_EFFICIENCY_MIN_VALUE = 0` なので、撃沈損失だけで海域効率を本当に0%へ落とせる。

初期100%、1隻撃沈なら、

```text
3.75 / N >= 1
```

すなわち `N <= 3` が1隻完全遮断の条件である。

### 8.2 複数海域の損失合計が100%以上

単独の海域が0%でなくても、経路上の損失合計が100%以上なら `R = 0` となる。

```text
Σ(1 - Ei) >= 1
```

例:

```text
海域A 62.5% → 損失37.5%
海域B 62.5% → 損失37.5%
海域C 62.5% → 損失37.5%

損失合計112.5% → 経路係数0%
```

### 8.3 配属船団0隻

必要船団が存在しても配属数が0なら、

```text
A = 0 / 必要数 = 0
```

となり、輸送は停止する。これは通商破壊による海域効率とは別の、純粋な船団在庫・割当不足である。

### 8.4 航路そのものが成立しない

港の喪失、海域通行禁止、接続経路の消滅などで海上経路が作れない場合も停止する。これは撃沈効率式の結果ではない。

### 8.5 小数効率は残っているが実量が0

効率が数%残っていても、輸送対象量が小さい場合は最終的な資源・補給の整数化によって0表示になりうる。したがって、「資源欄が0」は次のどれでも起こりうる。

```text
内部効率が本当に0%
配属船団が0隻
低効率 × 小輸送量が整数化で0
航路そのものが不成立
```

## 9. 回復処理

### 9.1 回復開始条件

撃沈時には対象海域レコードへ現在日付が保存される。`FUN_140e6aca0` は日次更新で、

```text
最後の撃沈日時
  + CONVOY_EFFICIENCY_REGAIN_AFTER_DAYS × 24時間
  <= 現在日時
```

になった海域だけを回復させる。

MOD値は5日である。

```text
CONVOY_EFFICIENCY_REGAIN_AFTER_DAYS = 5
```

したがって、最後の撃沈から5日間は回復しない。新たに1隻沈められると最終撃沈日時が更新され、待機期間が再び5日に戻る。

### 9.2 回復式

回復速度を `S` とすると、exeは次の式を使う。

```text
Enext = min(1.0, E + (1.10 - E) × S)
```

MODでは `S = 0.075`。

```text
Enext = min(1.0, E + (1.10 - E) × 0.075)
```

単純な毎日+7.5ポイントではなく、「110%と現在値との差」の7.5%を毎日回復する。上限は100%なので、最後は100%へ丸められる。

### 9.3 0%からの回復例

5日間の待機が終わり、回復開始時点を0%とする。

| 回復日数 | 海域効率の概算 |
|---:|---:|
| 0 | 0% |
| 1 | 8.25% |
| 2 | 15.88% |
| 3 | 22.94% |
| 5 | 約35.4% |
| 10 | 約59.6% |
| 20 | 約86.9% |
| 30 | 約99.4% |
| 31前後 | 100%へ上限処理 |

したがって、0%から完全回復するには、5日の無回復期間に加えて約31回の日次回復が必要になる。途中で再度撃沈されれば、効率がさらに差し引かれたうえで5日待機が再開する。

## 10. バニラとの比較

| define | バニラ | MOD `820039020` | 影響 |
|---|---:|---:|---|
| `CONVOY_EFFICIENCY_LOSS_MODIFIER` | 1.25 | 3.75 | MODは1隻当たり3倍の効率損失 |
| `CONVOY_EFFICIENCY_REGAIN_AFTER_DAYS` | 7日 | 5日 | MODは回復開始が2日早い |
| `CONVOY_EFFICIENCY_REGAIN_BASE_SPEED` | 0.04 | 0.075 | MODは回復速度が高い |
| `CONVOY_EFFICIENCY_MIN_VALUE` | 5% | 0% | MODでは撃沈妨害だけで完全停止可能 |

バニラで初期100%から1隻撃沈した場合は、海域の必要船団総数をNとして、

```text
Enew = max(0, 1 - 1.25 / N)
```

となる。MODは同じ分母に対して低下量が3倍である。

またバニラの最低値5%は、配属船団が残っている航路を通商破壊効率だけで完全な0%にしにくくする安全弁である。MODはこれを0へ変更しているため、小規模航路の完全遮断が明確に発生する。

## 11. AIの貿易中止閾値との区別

MODには次のdefineもある。

```text
MIN_CONVOY_EFFICIENCY_TO_CANCEL_TRADES = 0.4
MIN_CONVOY_EFFICIENCY_TO_START_TRADES  = 0.6
```

これらはAIが貿易を中止・再開するときの判断閾値であり、輸送経路そのものが40%未満で強制的に0へ切られる式ではない。

```text
40%未満
  = AIがその貿易を中止する判断材料

航路効率0%
  = 海域損失、船団充足率、経路不成立などの実計算結果
```

プレイヤーの既存貿易が機械的に40%で消える、という意味ではない。

## 12. 船団襲撃・船団護衛との関係

この資料の効率低下式は、輸送船海戦が終わって輸送船が実際に沈んだ後の処理である。その前段は別処理になる。

```text
船団襲撃任務
  発見抽選、追跡進捗、輸送船海戦の生成、初期参加艦数
        ↓
輸送船海戦
  攻撃命中、退却、護衛艦の増援、輸送船の損傷・沈没
        ↓
輸送船が沈没
  本資料の海域効率低下＋輸送船在庫減少
        ↓
資源輸入・補給などの実輸送量へ反映
```

したがって、

- 船団襲撃効率が高いほど、対象を発見して海戦を作りやすい。
- 船団護衛が機能するほど、襲撃艦を排除し輸送船撃沈を防ぎやすい。
- しかし1隻沈んだ後の `3.75 / N` という低下量は変化しない。

## 13. 実ゲームでの検証方法

### 13.1 1隻完全遮断の検証

1. 被害国に十分な輸送船在庫を用意する。
2. 他の船団航路と重ならない海域を選ぶ。
3. 対象航路の必要船団数を1～3隻にする。
4. 開戦前に航路効率100%、配属数＝必要数を確認する。
5. 輸送船を1隻だけ沈める。
6. 撃沈海域を通る航路効率と資源・補給量を確認する。

予備輸送船を十分に持たせる理由は、船団在庫不足Aと海域妨害Rを分離するためである。予備があるのに0%へ落ちれば、主因は海域効率である。

### 13.2 比例低下の検証

必要船団総数を10隻に揃え、1隻だけ沈める。

```text
予測海域効率 = 1 - 3.75 / 10 = 62.5%
```

配属率が100%、他海域に損失がないなら、航路効率も概ね62.5%になるはずである。

### 13.3 複数航路への波及検証

1. 同じ国の資源輸入と海上補給を同じ海域へ通す。
2. どちらか一方の輸送船をその海域で撃沈する。
3. 両方の航路効率が低下するか確認する。

exe上では効率が国別・海域別に保持されるため、両方へ同じ海域損失が使われると予測される。

### 13.4 回復式の検証

1. 海域効率を0%へ落とす。
2. その後は襲撃を完全に止める。
3. 5日間は回復しないことを確認する。
4. 回復開始初日に約8.25%となるか確認する。
5. 約31回の日次回復で100%へ戻るか確認する。

再度撃沈が起きると待機期間がリセットされるため、検証中は対象海域から襲撃艦を外す必要がある。

## 14. 実戦上の読み方

### 襲撃側

- 小規模な島嶼補給は、1隻撃沈だけで0%にできる可能性が高い。
- 交通量の多い海域は1隻当たりの低下が小さいが、必要船団数の約26.7%を短期間に沈めれば0%へ届く。
- 複数海域で損失を与えると、航路上の損失が加算されるため、単独海域を0%にしなくても経路全体を止められる。
- 5日以内に追加撃沈を続けると回復開始を延期できる。
- 撃沈数だけでなく、どの海域で沈めたかが重要である。

### 防御側

- 予備輸送船は配属率低下を防ぐが、海域効率低下そのものは防がない。
- 船団護衛は撃沈を防止することで間接的に効率を維持する。
- 一つの危険海域を複数の補給・資源航路が共有すると、一度の効率低下が広範囲へ波及する。
- 可能なら危険海域を迂回し、既に低下した海域を航路から外す方が回復待ちより即効性がある。
- MODでは最低効率0%なので、バニラより小規模航路が極端に脆い。

## 15. 確度と未確定点

### 高確度

- 輸送船1隻の破壊ごとに効率損失関数が1回呼ばれる。
- 低下量は `撃沈数 / 海域の必要船団総数 × LOSS_MODIFIER`。
- 分母は海戦参加数ではなく、海域を通る輸送経路の必要船団数合計。
- 効率は被害国ごと・海域ごとに保存される。
- 航路上の海域損失は平均ではなく加算される。
- 船団充足率は `配属数 / 必要数`。
- MODの最低効率は0%、回復待機は5日、回復速度は0.075。
- 回復式は `E + (1.10 - E) × 0.075`、上限100%。

### 注意が必要

- 資源・補給の最終整数表示で、何未満を0表示にするかは輸送用途ごとの後段処理に依存する。
- 海戦中の輸送船の一時拘束がUI更新へ与える短時間の影響は、本資料の撃沈後効率とは分けて考える必要がある。
- `CONVOY_LOSS_HISTORY_TIMEOUT_MONTHS = 3` は古い撃沈履歴を破棄する保存・履歴管理用で、海域効率が3か月固定で残るという意味ではない。

## 16. 最終要約

```text
撃沈海域の必要船団総数をNとする

1隻撃沈時の海域効率低下 = 3.75 / N

N <= 3
  → 1隻で海域効率0%

N = 4
  → 6.25%残る

N = 10
  → 62.5%残る

完全遮断の目安
  → 必要船団総数の約26.7%を回復前に撃沈

航路効率
  → 船団充足率 × 航路上の海域妨害係数

回復
  → 最後の撃沈から5日後に開始
  → Enew = min(100%, E + (110% - E) × 7.5%)
```

このMODの輸送船バランスは、「多数航路が集中する大海域では1隻の損失を薄める一方、小規模な孤立航路は1隻でも完全停止しうる」設計になっている。
