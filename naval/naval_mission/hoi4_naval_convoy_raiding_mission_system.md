# HOI4 海軍「船団襲撃」任務の内部処理

> 対象: HOI4 1.17系の提供Ghidraプロジェクトと、Workshop `820039020`（innovative balance v13.00）  
> 結論の中心: 船団襲撃は「海域に入った輸送船を即座に海戦へ入れる」処理ではない。任務効率の抽選、初回発見抽選、対象ごとの初回抽選、0～100%の追跡進捗を通過してから、輸送船海戦を新規作成する。

輸送船が実際に沈んだ後の資源・補給航路への影響は、[輸送船・輸送航路・通商破壊後の効率処理](./hoi4_convoy_transport_and_route_efficiency_system.md)を参照。

## 1. 結論

船団襲撃は、通常輸送船、部隊海上輸送、強襲上陸輸送を別種の対象として扱う。

```text
任務効率を計算
  ↓
部隊海上輸送／強襲上陸を先に検索
  ↓ 見つからなければ
通常輸送船を検索
  ↓
初回の基礎抽選＋任務効率抽選＋対象別抽選
  ↓
対象参照を保持して0～100%の発見進捗を加算
  ↓
100%到達時に共通海域を選び、輸送船海戦を生成
```

任務番号は `3 = CONVOY_RAIDING`、任務本体は `FUN_140f805c0` である。

特に重要なのは次の点である。

- 低い任務効率は索敵速度だけでなく、新しい対象を探す機会そのものを確率で失わせる。
- 通常輸送船と部隊輸送では、基礎発見率・初回抽選係数・追跡速度defineが分離されている。
- 部隊海上輸送／強襲上陸の探索が通常輸送船より先に呼ばれ、条件を満たすと通常輸送船の追跡を置き換えうる。
- 追跡進捗は100%へ達するまで保持されるが、対象が航路外へ出る、輸送が完了する、外交関係が変わるなどすると解除される。
- 100%到達後も、実際に海戦へ入る輸送船数には別の計算と乱数がある。

## 3. 船団襲撃任務効率

### 3.1 計算式

同じ艦隊・同じ担当範囲で活動する船団襲撃任務部隊をまとめて計算する。

```text
T = 活動中の船団襲撃任務部隊数
R = 担当海域数
C = coordination
M = 艦隊／国側の船団襲撃効率modifier

K = CONVOY_RAID_MAX_REGION_TO_TASKFORCE_RATIO
    × (1 + C × COORDINATION_EFFECT_ON_CONVOY_RAID_EFFICIENCY)

Eraw = clamp((T × K / R) × (1 + M), 0, 1)

Efinal = Eraw ^ MISSION_EFFICIENCY_POW_FACTOR
```

MOD値を入れると次になる。

```text
K = 1.0 × (1 + C × 1.0)
Efinal = clamp((T × K / R) × (1 + M), 0, 1)^1.7
```

対応defineは次である。

```lua
CONVOY_RAID_MAX_REGION_TO_TASKFORCE_RATIO = 1.0
COORDINATION_EFFECT_ON_CONVOY_RAID_EFFICIENCY = 1.0
MISSION_EFFICIENCY_POW_FACTOR = 1.7
```

### 3.2 海域を広げた例

coordinationと追加modifierを0とする。

| 任務部隊数 | 海域数 | 累乗前 | 最終効率 |
|---:|---:|---:|---:|
| 1 | 1 | 100% | 100% |
| 1 | 2 | 50% | 約30.8% |
| 1 | 3 | 33.3% | 約15.5% |
| 2 | 3 | 66.7% | 約50.2% |
| 3 | 3 | 100% | 100% |

このMODでは、coordinationが0なら原則として「1海域につき船団襲撃任務部隊1個」で100%になる。潜水艦を一つの大任務部隊にまとめて多数海域へ出すと、艦数が多くても効率は回復しない。式が数えるのは艦数ではなく任務部隊数だからである。

### 3.3 バニラとの差

バニラは次である。

```lua
CONVOY_RAID_MAX_REGION_TO_TASKFORCE_RATIO = 1.5
COORDINATION_EFFECT_ON_CONVOY_RAID_EFFICIENCY = 1.5
```

coordinationなしで1任務部隊を2海域へ出すと、バニラは `0.75^1.7 ≒ 61.3%`、MODは `0.5^1.7 ≒ 30.8%`。MODは広域襲撃に対して約半分の最終効率しか残らない。

## 4. 任務効率はどこへ使われるか

`FUN_140f805c0` は毎回 `FUN_140f72180` で `Efinal` を求め、初回対象探索関数へ渡す。対象を新規に探す際、効率が100%未満なら乱数を振り、乱数が効率以下の場合だけ探索を続ける。

概念的には次である。

```text
if random(0, 100%) > Efinal:
    この更新では新規探索を行わない
```

したがって、最終効率30.8%なら、初回探索の後続抽選へ進める更新機会自体が概ね30.8%まで減る。その後に基礎発見抽選と対象別抽選がさらに存在する。

任務効率は単純な「索敵進捗へ30.8%を掛ける」だけではない。この多段ゲートが、広域へ薄く潜水艦を出した場合の発見頻度を大きく下げる。

## 5. 通常輸送船の初回発見

### 5.1 第1ゲート――基礎発見抽選

現在追跡対象がなく、任務が有効で、交戦規定が「交戦しない」以外なら、まず次を使う。

```lua
CONVOY_DETECTION_CHANCE_BASE = 8.0
```

`FUN_140f7ec30` は専用乱数を振り、この基礎率を通過しない更新では通常輸送船候補を走査しない。

### 5.2 第2ゲート――任務効率抽選

基礎発見抽選を通過しても、前節の `Efinal` が100%未満なら別の乱数抽選を通す。二つは独立したゲートである。

単純化すると、候補走査まで進む率の上限は次になる。

```text
P(scan) ≒ CONVOY_DETECTION_CHANCE_BASE × Efinal
```

例として `Efinal = 30.8%` なら、基礎ゲート8%との積は約2.46%である。ただし、実際にはゲームの任務更新周期と固定小数点乱数を使うため、これをそのまま「毎時2.46%」と断定するのではなく、1回の船団襲撃更新あたりの概算として読むべきである。

### 5.3 第3ゲート――対象ごとの初回抽選

候補の輸送船航路ごとに、基礎発見値 `B` とその対象に対する追跡速度 `D` を組み合わせる。

```text
InitialScore_convoy
  = B × BASE_SPOTTING_EFFECT_FOR_INITIAL_CONVOY_SPOTTING
  + D × SPOTTING_SPEED_EFFECT_FOR_INITIAL_CONVOY_SPOTTING
```

MOD値は次である。

```lua
BASE_SPOTTING_EFFECT_FOR_INITIAL_CONVOY_SPOTTING = 2.4
SPOTTING_SPEED_EFFECT_FOR_INITIAL_CONVOY_SPOTTING = 0.12
```

候補ごとに乱数を振り、`InitialScore_convoy` が乱数以上なら、その輸送船航路を追跡対象として保存する。

`B` はレーダー、航空、情報差などを含む海域側の初期値で、詳細は哨戒資料の `FUN_140f70a70` 節と共通する。`D` は襲撃任務部隊の水上探知、相手側探知、速度差、天候、昼夜、coordinationなどを含む継続追跡速度である。

### 5.4 輸送船数

```lua
SPOTTING_MOD_FOR_CONVOY_COUNT = 0.2
```

輸送船数は `FUN_140f75570` の追跡速度計算へ渡され、大船団ほど見つけやすくする。ただし指数0.2のサブリニアなスケーリングなので、輸送船数が10倍になっても発見能力が10倍になるわけではない。

## 6. 部隊海上輸送と強襲上陸輸送

### 6.1 通常輸送船より先に検索される

任務本体は毎回、先に `FUN_140f7f6a0` で部隊海上輸送／強襲上陸輸送を探す。この関数が対象を設定しなかった場合だけ、通常輸送船用の `FUN_140f7ec30` を呼ぶ。

そのため、条件を満たす部隊輸送は通常輸送船より優先される。すでに通常輸送船を追跡していても、部隊輸送側の捕捉に成功すると、通常輸送船参照を解除して部隊輸送へ切り替える経路がある。

### 6.2 初回抽選

第1ゲートは共通で次を使う。

```lua
UNIT_TRANSFER_DETECTION_CHANCE_BASE = 8.0
```

候補別の初回抽選は対象種別で係数を分ける。

```text
通常の部隊海上輸送:
  InitialScore_transfer
    = B × 2.4 + Dtransfer × 0.12

強襲上陸輸送:
  InitialScore_invasion
    = B × 2.4 + Dinvasion × 0.12
```

MOD defineは次の通り。

```lua
BASE_UNIT_TRANSFER_SPOTTING_SPEED = 0.0
UNIT_TRANSFER_SPOTTING_SPEED_MULT = 5.0
BASE_NAVAL_INVASION_SPOTTING_SPEED = 0.0
NAVAL_INVASION_SPOTTING_SPEED_MULT = 10.0

BASE_SPOTTING_EFFECT_FOR_INITIAL_UNIT_TRANSFER_SPOTTING = 2.4
SPOTTING_SPEED_EFFECT_FOR_INITIAL_UNIT_TRANSFER_SPOTTING = 0.12
BASE_SPOTTING_EFFECT_FOR_INITIAL_NAVAL_INVASION_SPOTTING = 2.4
SPOTTING_SPEED_EFFECT_FOR_INITIAL_NAVAL_INVASION_SPOTTING = 0.12
```

強襲上陸輸送は追跡速度倍率10、通常の部隊輸送は5なので、他条件が同じなら上陸船団の継続追跡が速い。

## 7. 追跡開始後の0～100%進捗

初回抽選に成功すると、任務オブジェクトへ対象参照と発見進捗を保存する。

```text
通常輸送船参照       = mission + 0x90
部隊輸送参照         = mission + 0x98
発見進捗             = mission + 0x80
追跡中の共通海域参照 = mission + 0xe8
```

通常輸送船と部隊輸送は同時には保持しない。一方を設定すると、他方の参照と進捗を解除する。

各更新では概ね次の順になる。

```text
P = max(P, B)
P = P + D

if P >= 100%:
    海戦生成へ進む
```

内部の100%閾値は固定小数点で `10,000,000`。`FUN_140f81740` と `FUN_140f819a0` は、対象航路と襲撃任務の両方が含む共通海域から追跡海域を選び、同じ海域を可能な限り維持する。対象が別海域へ移れば、候補から乱数で再選択する。

### 対象が解除される主な場合

- 航路・輸送オブジェクトが終了または無効になった
- 相手との敵対関係がなくなった
- 対象航路が担当海域を通らなくなった
- 航行禁止海域の条件に反した
- 輸送部隊が上陸・到着した
- 対象がすでに別の無効な戦闘状態になった

解除時には参照、進捗、追跡海域が0へ戻る。

## 8. 100%到達後の海戦生成

### 8.1 通常輸送船

`FUN_140f6ec10` は、輸送航路と襲撃任務の共通海域から戦闘地点を乱数で選ぶ。その後、襲撃側任務部隊、輸送船航路、戦闘へ入れる輸送船数を `FUN_140b919e0` へ渡して新しい海戦を作る。

戦闘へ入る輸送船数は、概略次の構造である。

```text
raid_score
  = task_force_raid_value × CONVOY_ATTACK_BASE_FACTOR
  + 0.5を中心とする乱数項

route_divisor
  = max(1, route_region_count × CONVOY_ROUTE_SIZE_CONVOY_SCALE)

intercept_fraction
  = clamp(raid_score / route_divisor, 0, 1)

num_convoys_in_combat
  = max(1, convoy_count × intercept_fraction)
```

MOD値は次である。

```lua
CONVOY_ATTACK_BASE_FACTOR = 0.15
CONVOY_ROUTE_SIZE_CONVOY_SCALE = 0.01
```

`task_force_raid_value` は任務部隊の艦・装備・modifierから作る内部集計値で、単純な艦数ではない。乱数項があるため、同じ艦隊・同じ船団でも毎回同じ輸送船数が戦闘へ入るとは限らない。最低1隻は参加するよう下限が掛かる。

### 8.2 部隊海上輸送／強襲上陸

`FUN_140f6ef50` は輸送中の陸軍ユニット群から、担当海域内の有効な部隊・地点を選ぶ。同じ追跡海域を優先し、候補が複数なら乱数で一つを選んで `FUN_140b91b60` から海戦を作る。

部隊輸送に対する海軍攻撃には、周辺処理として次がある。

```lua
NAVAL_TRANSFER_DAMAGE_REDUCTION = 0.25
```

これは「発見率を25%へする」係数ではなく、1tickで部隊輸送へ極端な損害が出ないよう、戦闘・攻撃側で損害を調整する値である。

## 9. 乱数はどこにあるか

船団襲撃には少なくとも次の独立した乱数がある。

1. 通常輸送船の基礎発見抽選
2. 部隊輸送／強襲上陸の基礎発見抽選
3. 任務効率による探索実行抽選
4. 候補輸送船ごとの初回捕捉抽選
5. 候補部隊輸送ごとの初回捕捉抽選
6. 複数の共通海域から追跡海域を選ぶ抽選
7. 100%後に戦闘地点を選ぶ抽選
8. 通常輸送船の迎撃割合に入る乱数項
9. 部隊輸送の対象ユニット／地点選択

Ghidra上では、再現可能なゲーム用乱数関数 `FUN_142187010`／`FUN_1421871c0` が `navalmission.cpp` の各呼出地点情報とともに使われる。同じ発見式でも一回の乱数だけで全結果を決めているわけではない。

## 10. MODとバニラの索敵差

| define | MOD | バニラ |
|---|---:|---:|
| `BASE_CONVOY_SPOTTING_SPEED` | 0.05 | 0.0 |
| `CONVOY_SPOTTING_SPEED_MULT` | 5.0 | 1.0 |
| `CONVOY_DETECTION_CHANCE_BASE` | 8.0 | 4.12 |
| 初回通常船団への基礎発見値係数 | 2.4 | 0.05 |
| 初回通常船団への追跡速度係数 | 0.12 | 0.50 |
| `SPOTTING_MOD_FOR_CONVOY_COUNT` | 0.2 | 0.2 |
| `UNIT_TRANSFER_DETECTION_CHANCE_BASE` | 8.0 | 8.0 |
| 部隊輸送の初回係数 | 2.4 / 0.12 | 2.4 / 0.12 |
| `UNIT_TRANSFER_SPOTTING_SPEED_MULT` | 5.0 | 5.0 |
| `NAVAL_INVASION_SPOTTING_SPEED_MULT` | 10.0 | 10.0 |

MODの通常輸送船索敵は、基礎発見ゲートを4.12から8へほぼ倍増し、基礎追跡速度を0から0.05へ、速度倍率を1から5へ上げている。一方、初回対象別抽選では `B` の重みを0.05から2.4へ大幅増加させ、`D` の重みを0.50から0.12へ下げている。

つまりMODは、通常輸送船に対して「海域全体の航空・レーダー・情報支援で最初の足掛かりを得やすくし、一度捕捉した後の継続追跡も速くする」方向である。ただし任務効率の海域ペナルティはバニラより強いため、広域へ一個任務部隊を薄く出すと、この強化をかなり失う。

## 11. 再捕捉クールダウン

輸送船側には、一度襲撃された直後に同じ航路が連続で捕捉され続けるのを防ぐクールダウンがある。

```lua
CONVOY_SPOTTING_COOLDOWN = 0.25
CONVOY_SPOTTING_COOLDOWN_MIN = 24
CONVOY_SPOTTING_COOLDOWN_MAX = 120
CONVOY_SPOTTING_COOLDOWN_MIN_FROM_EFFICIENCY = 10
```

基礎は移動時間の25%、下限24時間、上限120時間。護衛効率による調整後の最小値は10時間である。

バニラは30%、36～168時間、効率補正後最小15時間なので、MODは再度襲撃可能になるまでの間隔が短い。高い通常輸送船発見率と組み合わさり、同じ航路への反復攻撃を起こしやすい。

## 12. 燃料・Org・任務共通値

```lua
MISSION_FUEL_COSTS[CONVOY_RAIDING] = 1.0
MISSION_FUEL_COSTS_PRIO_FACTOR[CONVOY_RAIDING] = 0.6
ORG_COST_WHILE_MOVING[CONVOY_RAIDING] = 0.2
ORG_COST_WHILE_MOVING_IN_MISSION_ZONE[CONVOY_RAIDING] = 0.0
MISSION_SPREADS[CONVOY_RAIDING] = 0.0
MISSION_EXP_RATIOS[CONVOY_RAIDING] = 0.005
MISSION_DOMINANCE_RATIOS[CONVOY_RAIDING] = 1.0
```

交戦規定が「交戦しない」で実効係数0の場合、初回船団探索のゲートを通らない。潜水艦の交戦規定は、発見後の対水上艦戦闘だけでなく、船団を新規捕捉できるかにも関係する。

## 13. 実戦上の読み方

- MODでは、まず「潜水艦の総数」より「担当海域数に対する任務部隊数」を確認する。
- 1任務部隊2海域で約30.8%、3海域で約15.5%まで落ちるため、広域襲撃は相当に不利。
- 通常輸送船の基礎発見自体はバニラより強いので、1海域1任務部隊に近づけると襲撃頻度が大きく上がる。
- 航空哨戒・レーダー・情報優位は初回の `B` を通じて、このMODでは特に強く通常輸送船捕捉を助ける。
- 強襲上陸輸送は継続追跡倍率10を持つため、担当海域へ侵攻船団が入れば通常船団より優先的かつ速く捕捉されやすい。
- 任務効率100%でも、基礎発見抽選と対象別乱数が残るので、船団が通過するたび必ず戦闘になるわけではない。
- 100%発見後の戦闘参加輸送船数にも乱数があるため、襲撃戦の規模は一定ではない。

## 14. 確度

### 高確度

- 任務効率式と1.7乗
- 任務効率が新規探索の独立した乱数ゲートになること
- 通常輸送船、部隊輸送、強襲上陸の別define
- 部隊輸送探索が通常輸送船探索より先に行われること
- `max(P, B) + D` と100%閾値
- 100%後に別関数で海戦を新規生成すること
- 複数段階に独立乱数があること
- MODとバニラの主要define差

### 中確度

- 通常輸送船数へ掛かる0.2の内部近似の厳密な丸め。define用途とサブリニアな方向は明確だが、固定小数点補助関数内の端数処理まで式へ展開していない。
- `task_force_raid_value` の日本語UI上の単一名称。艦・装備・modifierの集計であることは確認できるが、UIに一つの「船団迎撃力」として直接表示される値ではない。
- 戦闘へ入る輸送船数の乱数項に使われる共通定数の公開define名。加減算と0～1 clampは確認できるが、Ghidra上のグローバル名は未復元である。
