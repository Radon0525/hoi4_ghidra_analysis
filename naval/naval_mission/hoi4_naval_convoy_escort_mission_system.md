# HOI4 海軍「船団護衛」任務の内部処理

> 対象: HOI4 1.17系の提供Ghidraプロジェクトと、Workshop `820039020`（innovative balance v13.00）  
> 結論の中心: 船団護衛は輸送船へ物理的に常時随伴する処理ではない。担当海域全体へ抽象的な護衛効率を作り、味方輸送船が海戦へ捕捉された後、その効率を伴って護衛任務部隊を海戦へ参加させる。

## 1. 結論

船団護衛は次の流れで動く。

```text
担当海域・通過船団数・護衛艦数・護衛任務部隊数
  ↓
船団カバー率 × 海域カバー率
  ↓
1.7乗して最終護衛効率を作る
  ↓
味方輸送船が参加している海戦を検索
  ↓
護衛効率を引数として、選ばれた護衛任務部隊を海戦へ追加
```

任務番号は `4 = CONVOY_ESCORT`、任務本体は `FUN_140f7fd90` である。

重要な点は次の通り。

- マップ上で一隻一隻の輸送船へ護衛艦を貼り付ける処理ではない。
- 護衛効率には「護衛艦数で何隻の輸送船を覆えるか」と「任務部隊数で何海域を覆えるか」の二つのボトルネックがある。
- 二つの率は掛け算され、さらに `MISSION_EFFICIENCY_POW_FACTOR = 1.7` で低効率が強く罰せられる。
- 敵船団襲撃部隊を先に索敵して攻撃する任務ではなく、基本的には輸送船海戦への反応・増援任務である。
- 最終効率は、参加できる艦の割合と海戦への到着時間を決める下流処理へ渡される。

## 3. 船団護衛効率の計算式

### 3.1 変数

同じ艦隊・同じ担当海域範囲に属し、現在活動中の船団護衛任務部隊をまとめて計算する。

```text
S = 護衛任務中の総艦数
T = 護衛任務部隊数
C = その任務範囲で保護対象となる輸送船数
R = 担当海域数
M = 艦隊／国側の船団護衛効率modifier
Kc = 1隻が覆える輸送船数（coordination補正後）
Kr = 1任務部隊が覆える海域数（coordination補正後）
```

複数任務部隊のcoordinationが異なる場合、実装は各任務部隊の `Kc` を加重合計するのではなく、その平均値へ総艦数を掛ける。通常は同じ艦隊内で値が共通なので、次の簡略式でよい。

### 3.2 船団カバー率

```text
covered_convoys = S × Kc × (1 + M)

Econvoy = clamp(covered_convoys / C, 0, 1)
```

MODでは次の係数を使う。

```text
Kc = 25 × (1 + coordination × 1.0)
```

対応defineは次である。

```lua
CONVOY_DEFENSE_MAX_CONVOY_TO_SHIP_RATIO = 25.0
COORDINATION_EFFECT_ON_CONVOY_DEFENSE_EFFICIENCY = 1.0
```

つまりcoordinationと追加modifierを無視すれば、護衛艦1隻で最大25隻の輸送船をカバーする。

### 3.3 海域カバー率

```text
covered_regions = T × Kr × (1 + M)

Eregion = clamp(covered_regions / R, 0, 1)
```

MODでは次になる。

```text
Kr = 5 × (1 + coordination × 1.0)
```

```lua
CONVOY_DEFENSE_MAX_REGION_TO_TASKFORCE_RATIO = 5.0
COORDINATION_EFFECT_ON_CONVOY_DEFENSE_EFFICIENCY = 1.0
```

したがってcoordinationを無視すると、護衛任務部隊1個につき最大5海域を100%カバーできる。

### 3.4 最終効率

二つのカバー率を掛けてから1.7乗する。

```text
Eraw   = Econvoy × Eregion
Efinal = Eraw ^ MISSION_EFFICIENCY_POW_FACTOR

MISSION_EFFICIENCY_POW_FACTOR = 1.7
```

`FUN_14243d1e0` は固定小数点値の対数・指数処理で実際に累乗を行っている。したがって1.7はUIだけの説明値ではない。

低効率は見た目以上に悪化する。

| 累乗前 `Eraw` | 最終効率 `Efinal = Eraw^1.7` |
|---:|---:|
| 100% | 100% |
| 75% | 約61.3% |
| 60% | 約41.9% |
| 50% | 約30.8% |
| 33.3% | 約15.5% |
| 25% | 約9.5% |

## 4. 計算例

coordinationと追加modifierを0として計算する。

### 例1: 護衛艦4隻・輸送船100隻・1任務部隊・1海域

```text
MOD:
Econvoy = min(1, 4×25/100) = 1
Eregion = min(1, 1×5/1)    = 1
Efinal  = 1^1.7            = 100%

バニラ:
Econvoy = 4×12/100         = 0.48
Eregion = 1
Efinal  = 0.48^1.7         ≒ 28.7%
```

このMODは `CONVOY_DEFENSE_MAX_CONVOY_TO_SHIP_RATIO` をバニラの12から25へ上げているため、少数護衛艦で多数船団を守る能力が大幅に高い。

### 例2: 輸送船カバーは十分だが、1任務部隊で10海域

```text
Econvoy = 1
Eregion = 1×5/10 = 0.5
Efinal  = 0.5^1.7 ≒ 30.8%
```

艦数を増やすだけでは海域カバー不足を解消できない。同じ10海域を2個の護衛任務部隊で担当すれば、coordinationなしでも `2×5/10 = 1` となる。

### 例3: 護衛艦10隻・輸送船300隻・海域側は100%

```text
MOD:    Econvoy = 250/300 = 0.833 → Efinal ≒ 73.3%
バニラ: Econvoy = 120/300 = 0.400 → Efinal ≒ 21.1%
```

MODの船団保護能力は、特に大規模輸送路でバニラよりかなり高い。

## 5. 海戦へ参加するまで

### 5.1 護衛は敵を先制索敵しない

`FUN_140f7fd90` は、哨戒や船団襲撃のような0～100%索敵進捗を持たない。担当海域内に存在する海戦オブジェクトを走査し、味方・同盟国の輸送船が参加している海戦を探す。

これはゲーム上の船団護衛が、輸送船の航路へ抽象的なカバーを置き、襲撃が発生した時点で護衛艦を戦闘へ呼ぶ設計であることを示す。

### 5.2 参加候補の検証

海戦候補について少なくとも次を確認する。

- 海戦種別が海軍戦闘であること
- 味方または同盟側の輸送船が存在すること
- 海戦海域が護衛任務の担当範囲にあること
- 航行禁止海域の設定に反しないこと
- 自任務部隊が参加可能な状態であること
- すでに十分な護衛が入っている戦闘へ過剰参加しないこと

`FUN_14154a520` は海戦側の輸送船一覧を国・同盟関係で照合し、該当する輸送船数を数える。任務本体はその数と戦闘側の艦数を比較し、必要性の高い海戦を選ぶ。

### 5.3 最終効率を伴って海戦へ追加

選ばれた海戦に対し、`FUN_140b92960` が次を行う。

1. 任務部隊へ海戦位置を設定する。
2. 海戦オブジェクトへ任務部隊を追加する。
3. `FUN_140f71b10` が返した最終護衛効率を参加パラメータとして渡す。

したがって護衛効率は、単なるUI評価ではない。実際の海戦参加処理へ流れている。

## 6. 護衛効率が海戦参加へ与える影響

MODのdefineは次の通り。

```lua
BASE_JOIN_COMBAT_HOURS = 4
LOW_ORG_FACTOR_ON_JOIN_COMBAT_DURATION = 4.0
EFFICIENCY_TO_JOIN_COMBAT_RATIO_PENALTY = 1.0
EFFICIENCY_TO_TIME_TO_JOIN_COMBAT_PENALTY = 100.0
COORDINATION_EFFECT_ON_TIME_TO_JOIN_COMBAT = 1.0
```

コード上、`Efinal` は海戦追加処理へ渡される。defineコメントと下流の参加処理から、低効率は次の二方向に使われる。

- 最初から海戦へ入れる艦の割合を下げる。
- 残りの艦が戦闘へ到着する時間を増やす。

さらに低Orgは `LOW_ORG_FACTOR_ON_JOIN_COMBAT_DURATION` により参加時間を延ばす。よって船団護衛では、艦数が足りていても、多海域へ一個任務部隊を広げすぎて `Efinal` が落ちると「護衛艦が存在するのに初動へ間に合わない」状態が起こりうる。

この資料では、下流の艦ごとの到着時間丸めまで完全には命名できていないため、「効率50%なら必ず正確に50隻・追加50時間」とまでは断定しない。効率が参加割合と到着時間の両方へ渡ることは高確度である。

## 7. 海戦開始後の位置取り

船団護衛には、海戦海域の制海権差による位置取り補正がある。

```lua
DOMINANCE_EFFECT_ON_POSITIONING_FOR_CONVOY_ESCORT_MAX_RATIO = 2.0
DOMINANCE_EFFECT_ON_POSITIONING_FOR_CONVOY_ESCORT = 0.15
```

競合する制海権に対して必要値の2倍まで優位を取ると、船団護衛側の位置取りへ最大+15%が入る設定である。これは「海戦へ何隻・いつ参加するか」を決める護衛効率とは別の、海戦開始後のpositioning補正である。

## 8. MODとバニラの差

| define | MOD | バニラ | 影響 |
|---|---:|---:|---|
| `CONVOY_DEFENSE_MAX_CONVOY_TO_SHIP_RATIO` | 25 | 12 | MODは1隻で約2.08倍の輸送船をカバー |
| `CONVOY_DEFENSE_MAX_REGION_TO_TASKFORCE_RATIO` | 5 | 5 | 基礎海域数は同じ |
| `COORDINATION_EFFECT_ON_CONVOY_DEFENSE_EFFICIENCY` | 1.0 | 1.5 | MODはcoordinationによる追加伸びが小さい |
| `MISSION_EFFICIENCY_POW_FACTOR` | 1.7 | 1.7 | 低効率への非線形ペナルティは同じ |
| `CONVOY_SPOTTING_COOLDOWN_MIN_FROM_EFFICIENCY` | 10時間 | 15時間 | MODは高効率時の再捕捉抑止の最小値が短い |

総合すると、このMODは「護衛艦そのものの必要隻数」を大きく緩和する一方、広大な海域を少数任務部隊で担当したときの罰は残している。

```lua
MISSION_FUEL_COSTS[CONVOY_ESCORT] = 1.0
MISSION_FUEL_COSTS_PRIO_FACTOR[CONVOY_ESCORT] = 0.6
ORG_COST_WHILE_MOVING[CONVOY_ESCORT] = 0.2

MISSION_EXP_RATIOS[CONVOY_ESCORT] = 0.005

```

- 任務中の燃料係数は1.0だが、燃料優先度係数は打撃部隊・哨戒より低い0.6。
- 海域へ向かう移動にはOrgコスト0.2、任務海域内では0。
- 任務由来の海戦開始時散開は0。

## 10. 実戦上の読み方

- 輸送船数に対して艦数が足りるかだけでなく、担当海域数に対して任務部隊数が足りるかを見る。
- 1個の巨大護衛艦隊を広域へ置くより、5海域前後を目安に任務部隊を分けた方が海域カバーを維持しやすい。
- このMODでは1隻25輸送船なので、バニラ感覚で大量の護衛艦を置くと過剰になりやすい。
- ただし対潜探知、爆雷、速度、航続距離は効率式とは別であり、100%効率でも敵潜水艦を撃破できる設計でなければ損害は止まらない。
- 護衛効率100%は「輸送船が絶対沈まない」ではなく、「カバー不足による参加割合・到着時間ペナルティがない」に近い。

## 11. 確度

### 高確度

- 船団カバー率と海域カバー率の積
- 1.7乗による最終効率
- MODの25輸送船／隻、5海域／任務部隊
- 護衛任務が既存の輸送船海戦を検索して参加すること
- 最終効率が海戦参加処理へ渡ること
- MODとバニラの主要define差

### 中確度

- 艦隊／国側の追加護衛modifier `M` の日本語UI上の単一名称。内部modifier ID `0x10c` が両カバー能力へ掛かることは確認できる。
- 低効率から各艦の具体的な参加時刻へ変換する最終丸め。関連defineと引数伝播は確認済みだが、戦闘オブジェクト内部の全分岐は未命名である。
