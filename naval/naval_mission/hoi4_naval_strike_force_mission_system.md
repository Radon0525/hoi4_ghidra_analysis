# HOI4 海軍「打撃部隊」任務の内部処理

> 対象: HOI4 1.17系の提供Ghidraプロジェクトと、Workshop `820039020`（innovative balance v13.00）  
> 結論の中心: 打撃部隊は索敵任務ではない。完全発見された敵または既存海戦を艦隊側から割り当てられ、港から移動し、到達後に海戦へ参加する反応任務である。

## 1. 結論

打撃部隊の処理は、次の5段階に分かれる。

```text
哨戒などが敵を発見
  ↓
完全発見状態3、または既存海戦を候補化
  ↓
交戦規定・戦力比・修理状態・担当海域で割当
  ↓
打撃部隊が港から対象海域へ移動
  ↓
対象と接触できた時点で海戦へ参加
```

重要なのは次の点である。

- 任務番号は `2 = STRIKE_FORCE`。`0` は打撃部隊ではなく `HOLD`（待機）。
- `FUN_140f77990` は周囲の敵を自力で索敵しない。
- 通常の新規目標は、観測国から見た発見状態が3、すなわち100%発見済みの敵である。
- すでに海戦が始まっている対象には、その海戦を根拠に参加候補となる別分岐がある。
- 目標を得ても即時参加ではない。航路・現在位置・移動命令を経て、接触後に海戦参加関数が呼ばれる。
- 交戦規定は装飾ではなく、目標へ投入する自軍戦力の選択に使われる。

したがって、哨戒艦が発見した瞬間に主力艦が海戦へワープする仕組みではない。発見、割当、出撃、移動、海戦参加は別処理である。

## 3. 何が打撃部隊の目標になるか

### 3.1 通常の敵任務部隊

艦隊単位の候補収集 `FUN_140cfca10` は、敵任務部隊について `FUN_140c107c0` を呼び、返値が2より大きい場合だけ通常目標候補へ入れる。

```text
発見状態 0～2 → 通常の打撃部隊目標にはしない
発見状態 3     → 候補化できる
```

これは「打撃部隊自身が同じ海域を走査して発見する」という意味ではない。状態3は観測国側で共有される情報であり、哨戒、航空、レーダー、情報差などを含む別の発見処理が作る。

### 3.2 すでに始まっている海戦

同じ候補収集関数には、進行中の海戦から参加可能な対象を集める経路もある。目標再検証 `FUN_140f7bd10` でも、対象が参加可能な既存海戦にいる場合は完全発見状態3の再確認を省く分岐がある。

したがって厳密には、打撃部隊の起動条件は次の論理和である。

```text
通常目標: 完全発見状態3
または
救援・増援目標: 参加可能な既存海戦
```

「常に100%発見が必要」という説明は、新規の未交戦敵には正しいが、既存海戦への参加経路まで含めると不完全である。

### 3.3 候補から外れる主な条件

候補化・再検証では少なくとも次を確認している。

- 自国・同盟側ではなく、現在も敵対対象であること
- 自艦隊の担当海域と対象海域が重なること
- 航行禁止海域を通る対象でないこと
- 対象参照が有効で、消滅・編成解除されていないこと
- 自任務部隊が修理・移動・戦闘などの不適格状態でないこと
- 修理優先度に対応する最低修理率を満たすこと
- 既存海戦なら、その戦闘へ参加可能であること
- 通常目標なら完全発見状態3が維持されていること

`MIN_REPAIR_FOR_JOINING_COMBATS` はMODで次の値である。

| 修理設定 | 最低率 |
|---|---:|
| 修理しない | 0% |
| 低 | 50% |
| 中 | 70% |
| 高 | 90% |

## 4. 交戦規定と戦力比

`FUN_140d05140` は投入候補の任務部隊を交戦規定別にまとめ、各任務部隊の戦力ベクトルを合算する。`FUN_1418e9850` が、その合算値と敵側戦力を `AGGRESSION_SETTINGS_VALUES` の係数で比較する。

MOD値は次の通り。

```lua
AGGRESSION_SETTINGS_VALUES = {
    0,
    0.5,
    0.9,
    2.0,
    10000,
}
```

意味は「攻撃性」よりも、どれだけ不利な戦力差を許容するかに近い。

- 0: 交戦しない
- 0.5: 低リスク
- 0.9: 中程度
- 2.0: 高リスク
- 10000: 事実上ほぼ無条件

処理は、候補任務部隊を順に合算し、設定されたリスク係数で敵戦力に対応できるところまで目標を割り当てる。ここで使われる戦力値は単純な艦数ではなく、軽砲・重砲・魚雷・装甲対貫徹などを含む内部戦力ベクトルである。

MODの `AGGRESSION_LEVEL_BY_MISSION_*` はAIが自動で交戦規定を選ぶ際の値であり、プレイヤーが明示した交戦規定を上書きする普遍的なハード条件ではない。AIの打撃部隊は、海軍劣勢時に中程度、優勢時に最上位を選ぶ設定になっている。

## 5. 目標を受け取った後

### 5.1 目標参照の登録

`FUN_140f7eab0` は、任務部隊の目標参照を更新する。

1. 古い目標があれば対象側の登録リストから解除する。
2. 新目標が航行禁止海域に触れないか `FUN_140f7bfd0` で確認する。
3. 新目標への参照を保存する。
4. 対象任務部隊側にも「この任務部隊が反応中」という逆参照を登録する。

対象が消滅したり条件外になったりすると、`FUN_140f82850` が参照と逆参照を解除する。

### 5.2 港待機と出撃

有効な目標がない場合、`FUN_140f77990` は艦隊の基地位置を行動先として扱い、任務の活動フラグを落とす。これが打撃部隊の港待機に対応する。

有効な目標がある場合は、対象任務部隊の現在位置・所属艦隊・海域を解決し、自任務部隊の経路判定を呼ぶ。まだ同じ接触位置・同じ海戦にいなければ、目標側の海域／プロヴィンスを目的地へ入れ、`FUN_140f7d3c0(..., 1)` で移動命令を出す。

### 5.3 海戦参加

自任務部隊が対象へ接触できる状態になると、`FUN_140b93cd0` を呼ぶ。ここで初めて海戦参加が開始され、割り当てていた目標参照は解除される。

この構造から、100%発見後の到着時間には少なくとも次が影響する。

- 港から対象までの距離
- 実効艦隊速度
- 航路の可否と航行禁止海域
- 対象艦隊の移動
- 修理・燃料・Orgによる任務遂行状態
- 海戦が終了するまでに到達できるか

## 6. MODの燃料・Org・海戦開始時配置

### 6.1 燃料

```lua
MISSION_FUEL_COSTS[STRIKE_FORCE] = 1.0
MISSION_FUEL_COSTS_PRIO_FACTOR[STRIKE_FORCE] = 1.0
STRIKE_FORCE_ON_BASE_FUEL_COST_FACTOR = 0.00
IN_COMBAT_FUEL_COST = 2.0
FUEL_COST_MULT = 0.10
```

MODでは港内待機中の打撃部隊燃料コストが0である。バニラの `STRIKE_FORCE_ON_BASE_FUEL_COST_FACTOR` は0.25なので、MODは大型主力艦を港に置く運用の維持費をさらに軽くしている。出撃移動中は任務係数1.0、海戦中は2.0が使われる。

### 6.2 Organization

```lua
ORG_COST_WHILE_MOVING[STRIKE_FORCE] = 0.2
ORG_COST_WHILE_MOVING_IN_MISSION_ZONE[STRIKE_FORCE] = 0.0
```

担当海域へ向かう移動にはOrgコストがあるが、任務海域内移動用の追加コストは0である。Orgは出撃目標選択式へ直接乗算される値ではないが、移動・交戦可能状態や到着後の命中率を通じて間接的に重要である。

### 6.3 海戦開始時の散開

```lua
MISSION_SPREADS[STRIKE_FORCE] = 0.0
```

defineコメント上、値1は開始時に艦がいない方向の散開を表す。MODの0は任務由来の開始時散開ペナルティを与えない設定である。

## 7. 制海権とAI用define

MODは次を0にしている。

```lua
NAVAL_DOMINANCE_STRIKE_FORCE_FRACTION = 0.0000
NAVAL_DOMINANCE_STRIKE_FORCE_MULTIREGION_DECAY = 0.00
```

したがって、このMODでは打撃部隊の戦力を港に置くだけで得る打撃部隊固有の制海権倍率は無効化されている。一方、任務共通の `MISSION_DOMINANCE_RATIOS[STRIKE_FORCE] = 1.0` は残るため、制海権システム全体が無効という意味ではない。

次はAIの任務配置用であり、プレイヤー任務の毎時出撃判定そのものではない。

```lua
MAX_PATROL_TO_STRIKE_FORCE_RATIO = 4.0
STRIKE_FORCE_TARGET_RECALC_DAYS = 5
MIN_FUEL_RATIO_TO_NOT_IGNORE_STRIKE_FORCE_COST = 0.0
```

また、`NAVAL_STRIKE_FORCE_ATTACK_LIKELYHOOD_THR_*` はUIの「交戦しそうか」という表示閾値であり、実際の出撃ハード条件ではない。

## 8. 実戦上の読み方

### 哨戒が0なら打撃部隊は絶対に動かないか

通常の未交戦敵を新規捕捉する入口は失われやすいが、「絶対」ではない。航空・レーダー・別艦隊の哨戒などで完全発見状態3が作られるか、味方がすでに海戦へ入っていれば、打撃部隊の候補は生じる。

### 担当海域を増やすほど出撃が遅くなるか

打撃部隊本体には船団襲撃のような海域数／任務部隊数から作る任務効率式は確認できない。ただし、対象までの距離、航路、同時に発生する候補、哨戒側の発見密度は悪化しうる。MODでは打撃部隊固有の複数海域制海権減衰は0である。

### 主力艦だけでよいか

出撃可否だけなら索敵性能を打撃部隊へ大量に積む必要はない。しかし、到着速度、燃費、対潜能力、海戦開始後のスクリーン比率は別問題である。発見担当と撃破担当を分ける設計は実装と整合するが、遅すぎる打撃部隊は海戦終了前に届かない。

## 9. 確度

### 高確度

- 任務番号2が打撃部隊であること
- 完全発見状態3と既存海戦の二つの候補入口
- 戦力比・交戦規定による割当
- 目標参照、移動、接触後の海戦参加が別段階であること
- 航行禁止海域と修理率の再検証
- MODの燃料、Org、散開、制海権define

### 中確度

- 内部戦力ベクトル各成分のUI上の完全な名称対応。砲・魚雷・装甲等を含むことは呼出先から確認できるが、全16成分の名称は未命名である。
- 目標候補が複数ある場合の最終的な並び順。同一交戦規定内で経路／距離評価を持つことは確認できるが、全ての同点処理までは未確定である。
